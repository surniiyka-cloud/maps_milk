Управление доступом

Как будет работать личный кабинет

После авторизации каждый руководитель будет видеть показатели только своего ОП. Общекорпоративный обзор и права на другие филиалы настраиваются отдельно для администраторов.

Сейчас выбор подразделения — демонстрационный переключатель, а не защищённый вход. Реальные финансовые сведения здесь не используются.

Подключение 1С

Целевая схема передачи данных
Не подключено

1С → защищённый API → интерфейс

Сервер интеграции получает согласованные показатели из 1С, проверяет права доступа и передаёт агрегированные данные сайту. Пароли и ключи 1С никогда не должны храниться в браузере или GitHub Pages.

Для реального подключения потребуется API или HTTP-сервис 1С, серверная авторизация, регламент обновления и согласованная структура метрик.

Загрузка локальных данных

Быстрый предпросмотр без сервера

Импорт JSON

Для проверки структуры можно загрузить JSON со сводными KPI и реестром ДЗ. Файл читается только в текущем браузере и не отправляется в сеть.

Поля: revenue, revenuePlan, debt, orders, clients, debtors. Пример схемы доступен ниже.

Пример структуры данных

{
  "revenue": 12840000,
  "revenuePlan": 14000000,
  "debt": 4800000,
  "orders": 148,
  "clients": 67,
  "debtors": [
    {"name":"ООО Пример","region":"Киров","amount":450000,
     "days":21,"status":"danger","manager":"Менеджер"}
  ]
}

В рабочей системе данные должны поступать с сервера по авторизованному API, а не из публичного JSON в репозитории.
